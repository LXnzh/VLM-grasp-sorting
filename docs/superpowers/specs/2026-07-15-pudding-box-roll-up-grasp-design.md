# Pudding Box 滚边翘起抓取设计

## 1. 目标

让平放在桌面上的 `pudding_box` 在现有 Robotiq 2F-85 平行夹爪条件下实现稳定抓取，同时遵守本项目已经确立的最高优先级原则：

> 除 `tuna_fish_can`、`pudding_box`、`pear` 外，其他物品已经能够稳定抓取。本次修改只能由精确名称 `pudding_box` 主动进入，不能改变其他物品的候选生成、筛选阈值、排序、轨迹、夹爪参数或执行行为。

第一阶段的完成目标是：

1. 从盒体近侧边缘建立轻量上/下预夹持；
2. 以盒体远侧底边为桌面旋转轴，把近侧边缘滚起约 25–30 度；
3. 在近侧底部已经离开桌面后完全闭合；
4. 先完成 30 mm 试抬验证，再执行正常完整提升；
5. 全过程不让任何夹爪碰撞体进入桌面，不依赖与其他物品共享的阈值放宽。

第 5 项由 §13 的文件边界和 §15.1 的共享配置基线/非 Pudding 行为快照共同强制，而不只依赖代码审查者记住这条原则。

第一阶段只解决抓取和提升。倾斜盒体不能安全复用当前通用 `lift_return` 原位释放轨迹，因此自动放回/放置不在本设计范围内。仿真验证成功后由试验会话重置场景。

## 2. 问题的来龙去脉

### 2.1 最近一次失败发生了什么

最近一次 Pudding 失败日志位于：

```text
/tmp/my_course_experiment_sessions/20260715_131958_124068/trial_003/grasp_demo.log
```

FoundationPose 给出的目标世界位置为：

```text
[-0.4967, -0.9223, 0.8815]
```

而 MuJoCo 实时场景包围盒给出的真实目标中心为：

```text
[-0.2227, -0.5617, 0.9098]
```

两者的平面位置相差约 0.51 m。现有 `vertical` 路径随后把抓取库候选的 TCP 强行平移到包围盒中心：

```text
原候选 TCP: [-0.5464, -0.9567, 0.8994]
居中后 TCP: [-0.2227, -0.5617, 0.8994]
平移修正:   [+0.3237, +0.3949, 0.0000]
```

该操作破坏了抓取库候选原本相对盒角/盒边的位置关系。最终预抓姿态又因为夹爪关节/桌面碰撞和 IK 无有效目标而被 MoveIt 拒绝，夹爪没有进入闭合阶段。

因此最近失败不是单一参数偏差，而是三个问题叠加：

1. FoundationPose 平移明显不可信；
2. 通用 `vertical` 居中抹掉了边缘抓取所需的 TCP 偏移；
3. 候选本身需要下指接近盒底，桌面没有留出进入空间。

### 2.2 盒体和夹爪的几何冲突

Pudding 网格包围盒约为：

```text
138.6 mm × 129.4 mm × 39.6 mm
```

夹爪有效最大开口约为 85.16 mm。因此：

- 夹爪不能跨越 129–139 mm 的两个竖直侧面做普通水平对夹；
- 39.6 mm 厚度本身可以被夹住；
- 但盒子平放时，厚度方向对夹需要一个手指进入盒底，而桌面封住了这个空间。

把夹爪倾斜约 45 度、让一个 pad 压顶面而另一个 pad 压侧面也不能消除这个矛盾。两处接触法向不对向，平行夹爪闭合会对盒体产生净力矩，使盒体绕接触区转动并向外滑；它不是稳定的厚度对夹，反而比已经获得盒底支撑后的上下对夹更依赖摩擦。

离线检查全部 6,526 个 Pudding 抓取库姿态得到：

- 工具接近轴全部接近水平，距水平约 0–15 度；
- 夹爪闭合轴全部近似竖直，相对水平约 75.4–89.9 度；
- TCP 高度集中在盒体中部约 16.4–20.6 mm；
- 没有真正的水平短边对夹候选。

这些候选本质上是自由空间中的上/下表面对夹。放到桌面上后，下指必然被桌面阻挡。简单放宽现有 `vertical` 或 `side` 角度、高度阈值只会暴露更多物理不可达姿态，不能解决问题。

### 2.3 为什么不采用单次摩擦边缘夹

单次“顶面 + 侧面”斜夹不需要先翘起，但两个接触法向不是稳定的对向法向，盒体容易从夹爪中被挤出。用户判断该方案大概率摩擦不足，本设计同意这一判断，不把它作为主路径或失败回退。

## 3. 方案比较

### 3.1 顺序式预夹—滚起—锁紧（采用）

先建立轻量约束，再分段滚起，机械臂停稳后才完全闭合。盒体在闭合等待期间仍由下指和远侧桌面边共同支撑，不需要“夹爪速度快过重力”。动作能够逐阶段验证和中止，适合当前阻塞式夹爪 action。

### 3.2 滚动与夹爪闭合并发（第一阶段不采用）

当前夹爪有两种传输路径：action 路径等待 action 结果后返回；topic/native 路径以 `wait_for_result=False` 发送，可能较早返回。后者并不意味着已经具备可安全并发的共同时间轴，因为机械臂 Cartesian 轨迹、夹爪实际开度/力度反馈和接触验证仍没有统一同步点。

因此“不并发”不是建立在所有传输模式都阻塞这一假设上，而是一个独立的安全决策：第一阶段明确禁止机械臂滚动与完全闭合同时发生。无论使用 action 还是 topic/native，Pudding 状态机都必须等待当前夹爪命令的可验证结果和 bounds 稳定窗口后，才能进入下一机械臂状态。

### 3.3 推到桌边制造悬空（不采用）

该方案能直接制造盒底净空，但需要较大平移，容易干扰其他物品或把盒子推出桌面，违背“小范围、可隔离、失败关闭”的目标。

## 4. 隔离边界

顶层只允许以下精确分流：

```text
normalized selected object name == "pudding_box"
    -> Pudding 专属滚边规划与执行
其他所有名称
    -> 当前标准规划与执行路径原样运行
```

具体约束如下：

- 不修改 `VERTICAL_GRASP_OBJECTS`、`SIDE_GRASP_OBJECTS` 或共享 profile 映射；
- 不修改共享 `vertical`、`side`、`round_top`、`centered`、`top_down` 阈值；
- 不改变非 Pudding 的候选数量、候选矩阵、排序或步骤名称；
- 不改变共享夹爪默认力度、正常提升高度和放置行为；
- 不让 `tuna_fish_can`、`pear` 或 `tomato_soup_can` 调用 Pudding 代码；
- 第一版不抽象一个由 Tuna 和 Pudding 共同调用的滚动物体框架，避免同时改变两个未稳定对象；
- 纯数学函数以后可以复用，但本次全部保留为 `pudding_roll_planner.py` 内以下划线开头的私有函数，不放入共享 utility；只有精确 Pudding 分支能够调用。未来确需复用时另行设计、测试和批准。

除顶层精确分流和“禁止 Pudding 回退旧路径”的精确名称保护外，现有通用路径不重构。

## 5. 可信几何来源

Pudding 接触位置以 `/scene_clearance_bounds` 中唯一且名称精确匹配的实时目标 marker 为准，不以 FoundationPose 平移为准。FoundationPose 结果继续记录用于诊断，但不能决定 Pudding 的 TCP 平移。

当前发布端把仿真场景对象名原样写入 `Marker.text`，并把实时 **`base_link` 轴对齐 AABB** 写成在 `base_link` 中姿态为单位四元数的 `CUBE`。转换到规划世界后，必须保留 `T_world_bounds` 的三个轴和原始 half-extents，不能只复制 center/size 后假设两个坐标系轴相同。选择对象名和 `Marker.text` 必须通过同一个私有纯函数规范化：去除首尾空白、转小写、把空格/连字符替换为下划线，并移除可选的 YCB 数字前缀；规范化结果必须精确等于 `pudding_box`。这不是别名或模糊匹配。发布端当前固定场景名就是 `pudding_box`，因此两端名称同源。

该 marker 提供场景轴 AABB，而不是物体自身的可信 yaw。第一阶段因此只接受当前相对 `base_link` 轴对齐的固定布局，并通过 `T_world_bounds` 把场景轴转换到规划世界；不能从 AABB 臆造任意物体局部姿态。

场景数量和桌面期望值使用 Pudding 专属配置，而不是散落在验证代码中的裸字面量：

```text
PUDDING_EXPECTED_SCENE_OBJECT_COUNT = 6
PUDDING_EXPECTED_TABLE_HEIGHT_M = 0.890
```

运行时桌面高度不单独相信 `0.890 m`。监控器用初始六个有效 bounds 的底面 Z 中位数生成 `table_z_runtime`，要求各底面相对中位数的最大偏差不超过 5 mm，并要求 `table_z_runtime` 与 Pudding 专属期望值相差不超过 10 mm。后续桌面净空和平放恢复都使用 `table_z_runtime`；规划场景的实际 table collision mesh 仍用于完整碰撞检查。

进入规划前必须满足：

- 恰好存在一个规范化名称为 `pudding_box` 的 marker；
- marker 的本地单调时钟接收年龄不超过 0.25 s，避免混用 ROS 仿真时间与墙钟；
- 中心、姿态和尺寸有限且为正；
- 两个水平尺寸排序后位于 `[0.120, 0.150] m`；
- 高度位于 `[0.030, 0.050] m`；
- 目标底面与 `table_z_runtime` 的误差不超过 10 mm；
- 初始 MarkerArray 包含当前 assign 场景预期的六个唯一物体名称，且都能转换到规划世界坐标；执行期间名称集合不得变化；
- 当前目标仍为平放状态，初始高度不得已经达到滚起后的验证高度。

任何缺失、重复、过期、尺寸不符或桌面高度不符都在运动前失败关闭。不存在回退 FoundationPose 平移或固定世界坐标的路径。

## 6. 当前固定位置的空间余量

当前六物体固定场景中的 Pudding 仿真 AABB 为：

```text
center = [-0.3618, -0.0774, -0.0055] m
size   = [ 0.1386,  0.1294,  0.0396] m
```

对应最近日志中的规划世界中心：

```text
[-0.2227, -0.5617, 0.9098] m
```

盒体四个侧面到桌边的自由距离约为：

```text
仿真 -X: 888.9 mm
仿真 +X: 492.4 mm
仿真 -Y: 157.9 mm
仿真 +Y: 612.6 mm
```

仿真坐标与规划世界水平轴在该场景中的对应关系为：

```text
仿真 +Y -> 规划 -X: 612.6 mm（推荐接近侧）
仿真 -Y -> 规划 +X: 157.9 mm（推荐滚动侧）
仿真 -X -> 规划 -Y: 888.9 mm（Tuna 位于这一侧）
仿真 +X -> 规划 +Y: 492.4 mm
```

因此规划 `+X` 滚动方向的可用桌边余量是 157.9 mm，不是 492.4 mm；后面的约 94 mm 保守剩余量以 157.9 mm 为基数计算。

最近的非目标物体是 `tuna_fish_can`，位于仿真 -X / 规划 -Y 一侧，AABB 间隙只有约 75.5 mm，因此该侧不能容纳打开状态的完整夹爪包络。

推荐候选从规划世界 `-X` 侧接近盒体近边，盒体以规划 `+X` 远侧底边为旋转轴向 `+X` 滚起。该方向滚动侧初始余量约 157.9 mm，夹爪接近侧则有约 612.6 mm 空间。接触位置沿盒边向规划 `+Y` 偏约 20 mm，以进一步远离 Banana 和罐头一侧。

为避免在坐标轴映射尚未由运行时 `T_world_bounds` 复核前低估空间，这里按较大的水平尺寸 `L = 138.6 mm`、厚度 `H = 39.6 mm` 做保守桌边计算。以远侧底边为轴滚动角度 `theta` 时，盒体中心的水平移动量为：

```text
delta(theta) = L/2 * (1 - cos(theta)) + H/2 * sin(theta)
```

计算结果为：

```text
25 deg -> 14.9 mm
30 deg -> 19.2 mm
35 deg -> 23.9 mm
40 deg -> 28.9 mm
```

设计目标为 25–30 度，正常水平消耗不超过约 20 mm；即使按 35 度的 23.9 mm、30 mm 桌边安全边距和 10 mm 定位误差计算，仍保留约 94 mm 余量。因此当前固定位置的**物体滚动空间**充足。

这个结论不等于已经证明打开夹爪和相机支架也能通过。实现不能拿 85.16 mm pad 开口代替完整机构宽度，而必须用当前 URDF 正向运动学和 collision mesh 对每个样本验证：

- `MOVE_TO_PREPOSE` 和 `APPROACH_OPEN_SUPPORT` 使用开爪完整包络；
- `PRECLAMP` 和滚动微步使用实际预夹开度包络；
- `FULL_CLOSE`、试抬和提升使用闭合反馈对应的包络；
- 每个包络都必须位于桌面边界内，并分别满足桌面和非目标物体净空。

打开包络只决定接近能否通过；不能因为滚动时夹爪已经预夹就忽略接近阶段与 Tuna 的冲突，也不能拿较大的打开包络误判滚动阶段。若当前 URDF 的完整开爪包络不能放入 612.6 mm 接近空间，候选在运动前失败关闭。

## 7. 候选生成

Pudding 不再从 6,526 个旧库姿态中选最终执行姿态。第一阶段只支持已经确认净空的固定方向，专属规划器根据实时 bounds 生成一个小型候选集合：

1. 只从规划世界 `-X` 侧接近、向 `+X` 滚动；
2. 使用盒边中心和沿切向正/负 20 mm 三个接触位置；
3. 每个位置生成绕工具接近轴相差 180 度的两个腕部姿态，使相机支架可以选择远离障碍物的一侧；
4. 共至多 6 个候选，先做纯几何筛选，再做 IK 和 MoveIt 纯规划；
5. 当前固定场景优先规划沿 `+Y` 偏 20 mm 的接触位置，但仍必须逐候选验证实时完整包络；
6. 若固定方向的 6 个候选都不可达或有碰撞，立即停止，不自动换到 `-Y`、`+Y` 或 `+X` 接近侧。

每个候选必须同时具备：

- 从开爪支撑位姿沿工具接近轴反向平移至少 100 mm 得到 TCP 预位姿；不能用任意方向的 100 mm 欧氏距离代替；
- 滚动方向桌边净空至少 65 mm；它由 35 度保守物体位移 24 mm、定位误差 10 mm 和桌边安全边距 30 mm 相加后向上取整得到，是先于 IK 的硬门，不用其他方向的空间补偿；
- 完整夹爪、腕部和相机支架对非目标物体至少 30 mm 的预测净空；
- 开爪、预夹和闭合各阶段对应完整包络的桌面净空至少 5 mm；
- 开爪支撑姿态下，下指支撑边缘到盒体近侧壁/倒角的有符号法向间隙位于 `[0, 3] mm`，既不能预先穿入盒体，也不能离得过远而在闭合时先推盒子；
- 预位姿和全部滚动姿态均有有效 IK；
- 相邻 Cartesian 微步平移不超过 10 mm、转角不超过 5 度。

术语统一如下：5、10、15、20、25、30 度是必须停稳并读取新鲜 bounds 的 **validation checkpoint**；相邻 checkpoint 之间若为满足 10 mm 平移限制而插入更细的 **trajectory waypoint**，每个 waypoint 都做静态碰撞/IK 检查，但只有到达 checkpoint、TCP 收敛并完成稳定采样后才允许推进状态机。

没有候选通过时在运动前停止，不回退旧 Pudding 抓取库。

## 8. 夹爪几何和预夹标定

预夹姿态不能仅用一个 TCP 点判断桌面净空。实现必须从当前实际 URDF 和 collision mesh 建立夹爪模型，至少包含：

- 两个指尖和 pad；
- 两个 finger、knuckle 和 inner-knuckle；
- gripper base、安装适配器；
- 双相机支架和 Orbbec 碰撞体；
- TCP 到上述各 link 的实际变换。

在开爪、预夹和完全闭合三个状态下采样碰撞几何，并保存相对 TCP 的包络点。每个候选和滚动微步都用对应夹爪状态的完整包络计算最低世界 Z 和非目标净空。5 mm 桌面净空必须来自当前 URDF link 变换和 collision mesh 的正向运动学结果，不能用 TCP 高度或手工画出的简化矩形替代。

夹爪命令值不能直接按“85 mm 行程”线性猜测。第一项实现任务是在安全高位完成命令位置到实际 pad 间距的标定，并用当前 URDF 正向运动学复核。标定结果必须记录 URDF 来源和命令/间距表；标定缺失时 Pudding 分支禁止运动。

预夹目标由几何接触求解：

- 夹爪闭合轴从开始就近似平行于盒体厚度法向：候选排序优先不超过 5 度，10 度是不可放宽的硬上限；
- 下指的 pad 边缘接触盒体近侧底角上方的侧壁/倒角并提供向上支撑，不把任何碰撞网格预先插入盒底；其完整碰撞网格仍在桌面以上；
- 上指 pad 接触同一近侧区域的顶面；
- 预夹目标 pad 间距由这两个接触约束计算，并在**标定接触间距**基础上额外闭合 1–2 mm；它表示给控制器建立接触力的命令增量，不表示盒体厚度被压缩 1–2 mm，也不能从盒体厚度直接相减得到；
- Pudding 预夹力度使用独立 `PUDDING_PRECLAMP_EFFORT_N=50`；完全闭合使用独立 `PUDDING_FULL_CLOSE_EFFORT_N=140`，两者都由 Pudding 专属步骤显式传入；共享 `GRIPPER_EFFORT` 及其默认值不改变；
- 预夹动作必须记录目标位置、实际位置、effort、`stalled` 和 `reached_goal`。

当前 `gripper_control.py` 的 action 和 topic 两条路径都直接使用共享 `GRIPPER_EFFORT`。实施时只允许把接口扩展为 `send_gripper_command(position, effort=None)`：`effort is None` 时两条路径继续逐项使用原共享值；只有 Pudding 调用显式值。测试必须检查 action goal 的 `max_effort` 和 topic 调用参数都收到对应值，并证明非 Pudding 调用生成的请求字段、重试规则和结果判定逐项等价于修改前行为。

预夹命令完成后不立刻建立滚动基线。先等待至少 0.3 s 且取得至少 3 个新鲜、连续的 bounds 快照；相对预夹前基线必须同时满足：

```text
盒体平面中心位移 <= 0.005 m
盒体中心 Z 变化绝对值 <= 0.005 m
盒体 AABB 高度相对初始值变化绝对值 <= 0.005 m
```

预夹命令前记录绝对平放基线 `c_flat/h_flat`；稳定窗口通过并且夹爪反馈提供合理接触证据后，再记录实际 `T_world_tcp_preclamp`、滚动模型基线 `c0/h0` 和 TCP—中心相对向量并允许滚动。日志必须同时保留两组基线及其差值：滚动模型相对 `c0/h0` 计算，预夹位移、最终平放恢复和绝对倾斜高度仍相对 `c_flat/h_flat` 判断。这里不额外发送“探一下”的机械臂偏移，因为主动探测本身可能把盒子推走。若盒体已明显移动，则在滚动前失败，按 §12 的 0 度平放恢复条件处理。

如果真实 pad 几何无法同时满足上下接触、`[0, 3] mm` 支撑间隙和 5 mm 全包络桌面净空，则该候选无效；不能降低桌面净空来强行执行。

## 9. 正确的旋转轴和轨迹模型

一个容易混淆但必须明确的点是：

- 下指是移动的支撑/抬升接触点；
- 真正近似不动的旋转轴是盒体远侧底边；
- 不能把下指本身当作固定世界旋转轴。

若夹爪从世界 `-X` 侧接近并希望盒体向 `+X` 滚起，远侧 `+X` 底边必须保留在桌面作为旋转轴。下指随近侧底角沿圆弧向上、向 `+X` 移动，上指持续压住顶面。这样近侧盒底才会逐渐离开桌面，为下指形成真实的底部空间。

若错误地保持下指世界位置不变，盒体会向相反方向转，并且夹爪所在近侧不会获得设计所需的底部间隙。

### 9.1 从场景轴 AABB 得到远侧轴

第一阶段固定布局中，先从初始 marker 得到 `T_world_bounds` 和本地 half-extents。定义：

```text
c = T_world_bounds 的平移
R = T_world_bounds 的旋转
b0 = R * [1, 0, 0]            # base_link AABB X 轴在规划世界中的方向
b1 = R * [0, 1, 0]            # base_link AABB Y 轴在规划世界中的方向
z = [0, 0, 1]                 # 规划世界向上
r_desired = [1, 0, 0]         # 规划世界 +X，固定滚动方向
i_roll = argmax_i |dot(bi, r_desired)|, i in {0, 1}
r = sign(dot(b_i_roll, r_desired)) * b_i_roll
L = 2 * half_extents[i_roll]
H = 2 * half_extents[2]
```

必须满足 `r` 与 `r_desired` 的夹角不超过 5 度、另一个水平 bounds 轴与旋转边切向一致、bounds Z 轴与世界向上对齐；否则说明不是已批准的固定布局，运动前失败。

远侧底边参考点、近侧底角参考点和旋转轴切向分别为：

```text
p_far  = c + (L/2) * r - (H/2) * z
p_near = c - (L/2) * r - (H/2) * z
tangent = normalize(cross(z, r)) ≈ [0, 1, 0]
axis(lambda) = p_far + lambda * tangent
```

绕 `tangent` 的正角度旋转必须使 `p_near` 的世界 Z 增加；若符号检查失败，候选生成本身失败，不能在运行时试错。单元测试同时验证 `p_far` 在所有理想角度下保持不动、盒体中心向 `+X/+Z` 移动、下指接触点沿圆弧移动。

这个推导只因为第一阶段明确限制为相对场景轴对齐的固定布局才成立。AABB 不包含任意物体 yaw；如果经 `T_world_bounds` 转换后的尺寸轴不能与允许的规划世界轴对应，必须在运动前拒绝场景，不能用 FoundationPose 姿态补足。

### 9.2 期望轨迹和运行时残差

远侧底边上的世界参考点为 `p_far`，边方向单位向量为 `tangent`。定义绕该世界轴的增量变换：

```text
A(theta) =
    Translate(p_far)
  * RotateAbout(tangent, theta)
  * Translate(-p_far)
```

预夹稳定窗口成功后记录实际 `T_world_tcp_preclamp` 和稳定 AABB 中心 `c0`。在不发生显著滑移的理想模型中：

```text
c_model(theta) = A(theta) * homogeneous(c0)
T_world_tcp(theta) = A(theta) * T_world_tcp_preclamp
```

这样不需要从 AABB 伪造一个不可观测的物体局部姿态或 `T_object_tcp`；它只表达“如果远侧轴近似保持，TCP 和盒体中心应如何共同绕轴运动”。

实际执行使用 5 度微步，并通过 TCP 反馈和实时目标 AABB 检查模型是否成立。每个角度都计算模型目标中心 `c_model(theta)`、实测 AABB 中心 `c_measured(theta)`，以及模型/实际 TCP 到目标中心的相对向量，要求：

```text
模型与实测中心的平面残差 <= 0.015 m
模型与实测中心的 Z 残差绝对值 <= 0.010 m
实际“目标中心相对 TCP”与模型值的三维残差 <= 0.015 m
```

任一残差超限都说明远侧轴没有近似保持、盒体相对夹爪滑动或 bounds 异常，禁止进入下一微步。AABB 不能直接观测一条物体局部边，因此这里用中心轨迹残差间接验证轴模型，并明确记录这是近似证据而不是完整姿态观测。

该模型不是“相信物体一定刚性跟随”的假设，而是候选生成和期望轨迹；实时 bounds 用于识别滑动、未翘起或异常偏移。

## 10. 执行状态机

状态机按接触风险分为四组，风险等级决定允许的退出方式：

| 逻辑阶段 | 状态 | 风险 | 允许的中断方式 |
| --- | --- | --- | --- |
| 验证与部署 | `VALIDATE_SCENE` → `MOVE_TO_PREPOSE` → `APPROACH_OPEN_SUPPORT` | 低 | 无接触时可安全退回预位姿 |
| 预夹 | `PRECLAMP` | 中 | 只在确认仍平放后开爪撤退 |
| 滚动与锁定 | `ROLL_5_DEG_STEPS` → `VERIFY_TILT` → `FULL_CLOSE` | 高 | bounds 可信时按记录路径回滚，否则保持等待人工 |
| 提升与结束 | `TEST_LIFT_30MM` → `NORMAL_LIFT_AND_HOLD` | 高 | 只能沿已执行路径降低/回滚，禁止横向猜测撤退 |

### 10.1 `VALIDATE_SCENE`

验证精确目标名称、实时 bounds、桌面高度、目标尺寸、所有非目标 bounds 和候选净空。失败时不发送任何运动或夹爪命令。

### 10.2 `MOVE_TO_PREPOSE`

夹爪保持打开，通过 MoveIt 到达目标边缘外约 100 mm 的碰撞安全预位姿。MoveIt 失败则尝试下一个已经离线通过几何筛选的 Pudding 候选；所有候选失败后停止。

### 10.3 `APPROACH_OPEN_SUPPORT`

切换到低速 Cartesian 控制，分段到达开爪边缘支撑姿态。每步验证实际 TCP 收敛和开爪完整包络桌面净空。到达后还必须输出并验证：下指支撑边缘到盒体近侧壁/倒角的有符号法向间隙位于 `[0, 3] mm`，从当前开度到标定接触开度的预计行程有效，闭合扫掠体不会先撞侧壁把盒子水平推出。

### 10.4 `PRECLAMP`

把 50 N 显式写入本次 action goal 或 topic 调用，命令标定得到的部分闭合位置。预夹结果必须落入标定允许窗口，并提供合理接触证据。拒绝、异常早停、闭合过深或与空夹结果一致均停止后续滚动。

命令结束后执行 §8 的 0.3 s/3 快照稳定窗口。只有平面位移不超过 5 mm、中心 Z 和 AABB 高度变化都不超过 5 mm、盒体仍平放时，才记录实际 TCP/AABB 滚动基线并转入滚动；这项检查是 `PRECLAMP -> ROLL_5_DEG_STEPS` 的硬过渡条件。由于场景 bounds 不提供物体真实 roll/pitch，设计不伪造角度观测，而用 AABB 高度、中心变化和操作员视觉作为夹偏证据。

### 10.5 `ROLL_5_DEG_STEPS`

按 5、10、15、20、25、30 度执行远侧底边旋转轨迹。每步完成后检查：

- TCP 平移和姿态误差；
- 目标 bounds 新鲜度；
- 目标高度是否总体单调增加；
- 目标平面中心相对初始值是否小于 40 mm；
- §9.2 的模型中心残差和目标中心相对 TCP 残差；
- 夹爪与桌面、非目标物体的预测净空；
- 预夹命令是否仍保持有效。

不要求每个 5 度步的高度严格数学单调，以容忍 AABB 离散和接触瞬态；但允许单步回退最多 5 mm，连续两步不增高即判定没有有效滚起。

在 0、5、10、15、20、25 和 30 度全部记录“命令角度、实际 TCP、AABB 高度、中心 Z、平面位移和模型残差”，形成当前 mesh/发布器的经验角度—高度曲线。该曲线只能在分阶段试验后用于修改下一次运行的 Pudding 专属阈值，禁止在同一次运行中观察结果后动态放宽门限。

### 10.6 `VERIFY_TILT`

进入完全闭合前必须满足：

```text
目标 AABB 高度 >= 0.085 m
目标中心 Z 增量 >= 0.020 m
目标平面位移 <= 0.040 m
最新 bounds 年龄 <= 0.25 s
```

为避免高估翘起高度，这里用较小的水平尺寸 129.4 mm 与 39.6 mm 厚度计算保守理论下界；运行时仍以 §9.1 从 `T_world_bounds` 得到的真实滚动尺寸为准：

```text
25 deg -> 90.6 mm
30 deg -> 99.0 mm
35 deg -> 106.7 mm
```

0.085 m 阈值故意低于 25 度理论值，为网格、接触和 AABB 抖动留出余量，但仍明显高于初始约 0.040 m。阶段 7–10 必须先建立实际角度—高度曲线；如果 25 度的稳定实测高度不能以足够余量跨过 0.085 m，则在进入完全闭合试验前重新审查 Pudding 专属阈值或目标角度，不能临场绕过 `VERIFY_TILT`。

### 10.7 `FULL_CLOSE`

机械臂停稳并保持滚起姿态，然后才发送完全闭合。下指此时位于已经抬起的近侧盒底区域，上指位于顶面，闭合主要跨越约 39.6 mm 厚度。结果必须显示在与盒体厚度相符的开度发生接触；空夹到底或不合理早停均失败。

### 10.8 `TEST_LIFT_30MM`

以 5–10 mm 微步竖直抬升总计 30 mm。成功条件为：

```text
目标中心 Z 跟随增量 >= 0.020 m
目标相对 TCP 的平面漂移 <= 0.015 m
目标 bounds 始终新鲜
夹爪闭合反馈保持有效
```

### 10.9 `NORMAL_LIFT_AND_HOLD`

试抬通过后执行现有正常提升高度，但不进入通用 `lift_return` 原位释放。保持 5 s 并记录成功，然后 Pudding 试验进程结束，由仿真会话重置场景。自动放置需要独立设计和批准。

## 11. 运行时 bounds 监控

Pudding 专属执行器在运动开始前建立 `/scene_clearance_bounds` 持久订阅，按规范化精确名称缓存目标和非目标 marker。现有 `MultiThreadedExecutor` 允许回调在工作线程执行动作时继续更新。

监控器职责仅包括：

- 验证完整 MarkerArray；
- 转换到规划世界坐标；
- 记录接收时间、目标中心、尺寸和所有非目标 bounds；
- 提供带最大年龄约束的原子快照；
- 在目标消失、重复、尺寸异常或场景不完整时失败关闭。

目标键来自 `Marker.text`，并与选择对象名使用 §5 同一个规范化规则；恰好一个规范化键为 `pudding_box` 才有效。新鲜度使用本地接收时间判断，不直接拿 ROS header stamp 与墙钟相减。

监控器必须是只在精确 Pudding 分支构造的独立实例，拥有自己的 subscription、`threading.Lock` 和快照缓存。快照使用不可变 `@dataclass(frozen=True)`；回调先在局部变量中完成完整验证和深复制，再在同一把锁内一次性替换快照引用，读取方也在锁内取得引用后再离开临界区。禁止分别更新时间戳、目标和障碍物字段，避免读到混合代际数据。

回调不写模块级可变变量，不挂接到现有 `pick_place_planner` 实例，也不修改其他物品的一次性 bounds 加载逻辑。Pudding 运行结束后销毁订阅。隔离测试在非 Pudding 路由中断言监控器从未构造、没有新增订阅，现有 clearance 数据和回调对象身份均不改变。

## 12. 失败与撤退

失败处理取决于接触阶段：

### 12.1 接触前

MoveIt、IK、bounds 或开爪接近失败时，直接退回当前 Pudding 预位姿或保持安全停止。不会影响物体。

### 12.2 预夹后、完全闭合前

若目标 bounds 仍新鲜，且目标位移/高度位于可恢复窗口，则保持预夹并按已经成功执行的角度以 5 度反向微步回滚到 0 度。每个反向微步继续使用预夹完整包络、TCP 收敛、bounds 新鲜度和 §9.2 模型残差门限；每个目标最多发送 3 次运动尝试，任一步连续失败、滑移扩大或 bounds 失真都立即转入 §12.3 的“保持 + 人工重置”，不能无限重试。

到达命令 0 度不等于盒体已经平放。只有至少 0.3 s 内连续 3 个新鲜快照同时满足以下条件才允许张开：

```text
|AABB 高度 - 初始高度| <= 0.010 m
|中心 Z - 初始中心 Z| <= 0.010 m
|AABB 底面 Z - 桌面 Z| <= 0.010 m
平面中心相对初始位置位移 <= 0.020 m
```

若条件不成立，则保持当前臂位姿和预夹命令，等待人工重置；禁止因为“角度命令已经回到 0”就自动开爪。

### 12.3 bounds 丢失或异常滑动

若目标 marker 丢失、场景不完整、平面位移超过 40 mm 或姿态结果无法判断，则保持当前机械臂和夹爪命令，不自动张开、不执行横向撤退。仿真中等待人工检查后重置场景。该策略避免在不知道盒体位置时把它弹出或让夹爪刮过桌面。

### 12.4 完全闭合后或试抬中

若 bounds 显示物体仍跟随夹爪，则保持已经成功的完全闭合命令，不在半空放松到预夹；沿已执行试抬路径降低，再使用闭合反馈对应的完整包络按反向滚动路径落回。远离预计支撑面时最多使用 10 mm 降低 waypoint；进入预计支撑面上方 6 mm 后改用最多 3 mm waypoint。每步比较命令降低量与目标中心实际 Z 变化：若目标底面已进入 `table_z_runtime ± 10 mm` 且中心实际下降显著小于命令下降，判定桌面已经承重，立即停止继续压低并进入平放稳定验证。

反向微步同样受每步最多 3 次尝试和全部残差/净空门限约束。只有通过 §12.2 的平放稳定窗口、确认盒体重新受桌面支撑后才张开。若 bounds 不可信或任一恢复门限失败，则保持并等待人工重置。

任何失败都禁止进入正常完整提升；不存在单次摩擦边缘夹、旧抓取库或放宽共享阈值的回退。

## 14. 分阶段验证

每个阶段都是独立试验，只有前一阶段通过才能解锁下一阶段：

1. **离线几何**：输出目标 bounds、由 AABB 推导的 `p_far/tangent`、固定候选侧、接触点、三态完整夹爪最低 Z、所有障碍物净空、支撑间隙和滚动微步。
2. **夹爪标定**：在安全高位建立命令值到 pad 间距映射，验证开/预夹/闭合包络。
3. **MoveIt 纯规划**：验证预位姿、相机支架 180 度翻转方案、IK 和完整机器人碰撞。
4. **停在预位姿**：不接近物体、不闭合。
5. **停在开爪支撑姿态**：用实际 URDF 正向运动学自动记录完整机构最低 Z 和 `table_z_runtime` 差值，只有不低于 5 mm 才通过；同时验证 `[0, 3] mm` 支撑间隙。操作员目视只作为异常接触的辅助证据。
6. **只执行预夹**：验证顶面/底角接触、显式 50 N goal、0.3 s/3 快照稳定窗口、平面位移不超过 5 mm、中心 Z/AABB 高度变化不超过 5 mm；操作员额外观察盒体是否明显夹偏。
7. **滚到 10 度**：停止并记录 bounds 高度、位移、TCP 相对残差和经验曲线样本。
8. **滚到 20 度**：重复检查和记录。
9. **受控回滚到 0 度**：在继续更大角度前先验证恢复路径、尝试上限和平放稳定窗口；该阶段必须在独立试验中成功。
10. **滚到 25–30 度**：在新的场景试验中通过倾斜阈值，并完成经验曲线。
11. **完全闭合但不抬升**：验证厚度方向接触和显式 140 N goal。
12. **30 mm 试抬**：验证盒体跟随。
13. **完整提升并保持**：不自动放回。

所有首次在线接触/运动阶段均要求操作员观察，禁止把第一次预夹、第一次滚动、第一次回滚、第一次闭合和第一次提升合并为无人值守动作。

“受控回滚到 0 度”是对 §12.2 同一恢复方法的独立验证命令，不是 §10 正常前进状态机中的新状态。验证命令只能在本次试验到达 20 度后触发；回滚完成即结束本次试验并重置场景，不能在同一次会话中从回滚结果继续解锁 25–30 度或完全闭合。真实失败恢复不受前进阶段上限阻止。

## 15. 自动化测试

### 15.1 精确隔离

- 只有规范化精确名称 `pudding_box` 进入新分支；
- 所有其他已知物品进入原路径；
- 对固定输入比较非 Pudding 候选矩阵、排序、步骤名称、夹爪目标和 debug 行为，要求与修改前一致；
- 从配置中的完整对象映射动态枚举所有非 Pudding 名称，而不是只手工维护代表性名单；
- 特别覆盖 `gelatin_box`、`foam_brick`、`rubiks_cube`，证明它们虽然同属旧 `vertical` 类别也不受影响；
- 特别覆盖 `tuna_fish_can` 和 `pear`，证明三个未稳定对象之间也没有串路由；
- 非 Pudding 路由不构造 `pudding_scene_monitor`、不新增订阅、不写任何 Pudding 缓存；
- 通用 planner 收到精确 Pudding 时在入口抛异常，其他全部对象的返回值与调用顺序不变；
- `send_gripper_command(position)` 的 action/topic 参数与修改前完全一致，只有显式传 `effort` 的 Pudding 调用改变 goal。
- 在清理 `GRASP_*` 环境变量的子进程中比较非 Pudding 共享配置基线，任何共享常量或对象映射变化都使测试失败；
- 规范化等价输入 `Pudding_Box`、`pudding box`、`pudding-box`、`008_pudding_box` 和尾随空格按 §5 规则得到精确 canonical key，允许进入 Pudding 分支；近似但非等价的 `pudding_boxes`、`my_pudding_box`、`pudding_box_extra`、空值和随机无效名称绝不能进入 Pudding 分支；
- 对随机生成的名称做属性测试：只有规范化结果精确等于 `pudding_box` 才能选择专属路由，其他有效对象保持旧路由，无效对象按原有验证失败。

### 15.2 几何和净空

- bounds 尺寸、时间、唯一性和桌面高度失败关闭；
- 只生成规划 `-X` 接近、`+X` 滚动候选，切向 `-20/0/+20 mm` 偏移方向正确；
- 其他三个接近侧即使 IK 可达也不会成为第一阶段回退；
- 当前固定场景优先候选具有预期约 157.9 mm 滚动侧余量；
- `p_far = c + L/2*r - H/2*z`、`tangent = cross(z,r)` 的符号和尺寸轴正确；
- 远侧底边在理想滚动模型中保持不动；
- 下指接触点沿圆弧移动，而不是错误地保持世界位置不变；
- 开爪、预夹和闭合包络只用于各自状态，每个包络点在对应样本中满足 5 mm 桌面净空；
- 开爪支撑间隙位于 `[0, 3] mm`，越界候选被拒绝；
- 任何非目标净空低于 30 mm 的候选被拒绝；
- 相机支架 180 度变体能够独立排序和拒绝。

### 15.3 状态机

- 步骤顺序严格为验证、预位、开爪接近、预夹、滚动、倾斜验证、完全闭合、试抬、正常提升；
- 任何前置步骤失败都阻止后续步骤；
- bounds 过期、连续两步不增高、位移超限、空夹到底和试抬不跟随分别失败关闭；
- 预夹稳定窗口失败会阻止第一步滚动；
- 模型中心残差或目标中心相对 TCP 残差超限会阻止下一微步；
- 可恢复失败按已执行角度反向回滚；
- 每个反向目标最多 3 次尝试，回到命令 0 度但未通过平放稳定窗口时仍禁止开爪；
- bounds 不可信时保持而不自动张开；
- 第一阶段不调用通用 `lift_return` 释放。

## 16. 验收标准

只有同时满足以下条件才把 Pudding 抓取视为稳定：

- 运行路径只由精确 `pudding_box` 分支触发；
- 第一阶段只使用规划 `-X` 接近、`+X` 滚动，固定方向失败时不自动换侧；
- 初始平放状态下没有任何手指或夹爪碰撞体进入盒底与桌面之间；
- 开爪接触、预夹和全部滚动微步的完整夹爪桌面净空均不低于 5 mm；
- 开爪支撑间隙位于 `[0, 3] mm`；
- 预夹不会把盒体中心推移超过 5 mm，中心 Z 和 AABB 高度变化都不超过 5 mm；
- 滚动全过程平面位移不超过 40 mm，且每步模型/实测残差位于 §9.2 窗口；
- 盒体以远侧底边为实际近似旋转轴达到至少 0.085 m AABB 高度；
- 完全闭合主要捕获约 39.6 mm 厚度，而不是尝试跨越 129–139 mm 平面尺寸；
- 三次独立新场景 30 mm 试抬连续成功；
- 随后三次独立新场景完整提升连续成功；
- 非 Pudding 固定输入回归完全不变；
- Pudding 监控器没有共享可变状态，非 Pudding 路由不会构造或订阅它；
- 没有共享阈值、共享执行行为或其他物品默认参数被改变；
- 第一阶段不自动释放倾斜盒体。

这里的“独立新场景”是三次各自完整的仿真 reset → 新鲜感知 → 新规划 → 新执行链路；不是在同一次运行中重复抬放，也不表示允许改变 §17 排除的固定槽位和初始朝向。

## 17. 非目标

本设计不包括：

- 修复 FoundationPose 或 SAM2 对 Pudding 的平移误差；
- 修改其他 `vertical` 物品的居中逻辑；
- 实现 Tuna 或 Pear 的抓取；
- 抽象跨对象的通用滚动物体框架；
- 真实硬件部署；
- 自动放回、自动放置或倾斜盒体释放；
- 当前固定方向失败后的其他接近侧自动搜索；
- 任意初始 yaw 或非固定槽位布局下的通用 Pudding 操作；第一阶段只支持当前相对 `base_link` 轴对齐的固定布局，其他布局必须重新通过候选和净空验证；
- 在失败后猜测物体位置并继续运动。

## 18. 第一轮审阅意见的处理结论

本轮审阅提出的机械和隔离问题已经转成设计硬约束：

- 补充 45 度顶面/侧面斜夹的非对向受力问题；
- 明确仿真轴到规划轴的映射，确认 `+X` 滚动侧为 157.9 mm，并要求用三态完整机构包络验证而不是只看物体中心；
- 第一阶段从“四侧择优”收紧为固定 `-X` 接近、`+X` 滚动，失败即停；
- 加入开爪支撑间隙、预夹后稳定窗口和显式 50/140 N 传参；
- 给出从 `T_world_bounds` 及场景轴 half-extents 推导 `p_far` 和 `tangent` 的公式，并增加每步模型残差监控；
- 在闭合前建立实际角度—AABB 高度曲线，不允许同次运行动态放宽阈值；
- 恢复路径增加每步尝试上限和平放稳定窗口，命令回到 0 度不再被视为足够证据；
- 明确 Pudding 监控器只含分支私有状态，通用 planner 的 Pudding 保护在入口直接抛异常。

仍然必须通过实施前离线 URDF 正向运动学验证的未知量是：当前打开夹爪、腕部和相机支架完整包络能否实际通过 612.6 mm 接近空间，以及 `[0, 3] mm` 支撑间隙与 5 mm 桌面净空能否同时成立。设计不会在没有这两个结果时宣称动作可执行。

## 19. 第二轮审阅意见的处理结论

第二轮审阅给出“满足四项闭环后批准”的结论。四项在当前版本中的落点为：

1. bounds 到 `p_far` 的完整坐标链已由 §5 和 §9.1 的 `T_world_bounds + half-extents` 推导明确；
2. 回滚末端平放验证已由 §12.2 的连续快照、高度、中心 Z、底面 Z 和平面位移门限明确；
3. 线程安全快照已由 §11 的不可变 dataclass、单锁写时复制和原子引用替换明确；
4. 名称 fuzz/路由性质测试与 gripper effort 回归已由 §15.1 明确。

审阅文本中的“四侧/24 候选”、`T_world_object(theta)` 和“回到 0 度即开爪”引用来自第一轮修订前版本；当前设计已经分别替换为固定方向最多 6 个候选、直接对 TCP/AABB 基线应用轴增量变换，以及显式平放稳定窗口。

本轮另外吸收了仍适用于当前版本的建议：

- 说明 action 与 topic/native 夹爪路径的差异，并把顺序执行定义为独立安全选择；
- 添加 Pudding 专属场景数量/桌面期望值，并从初始 bounds 底面中位数生成运行时桌面高度；
- 明确 100 mm 是沿工具接近轴后退，65 mm 门限来自 `24 + 10 + 30 mm`；
- 区分 trajectory waypoint 和 validation checkpoint；
- 把预夹允许平面位移收紧到 5 mm，并用 AABB 高度变化检测夹偏；
- 增加状态风险分组、低速落桌和共享配置基线测试。

对名称测试不采用“原始字符串大小写/空格变化一律拒绝”的建议，因为项目既有边界和本设计从一开始约定的是**规范化后的精确名称**。因此 canonical 等价写法允许进入；只有规范化结果精确等于 `pudding_box` 才允许进入，复数、前后缀和随机近似名称全部拒绝。

## 20. Spec/Plan 综合审阅的一致性说明

综合审阅中引用的“四侧/24 候选”属于第一轮修订前版本。最终批准版 §7 已明确第一阶段只生成规划 `-X` 接近、`+X` 滚动的最多 6 个候选，失败即停；这不是 plan 对 spec 的额外缩减。该范围只对当前固定槽位和相对 `base_link` 轴对齐朝向有效，布局变化必须重新设计/验证。

612.6 mm 也不是数字笔误：§6 的坐标映射是“仿真 `+Y` → 规划 `-X`”，所以规划 `-X` 推荐接近侧为 612.6 mm；888.9 mm 是“仿真 `-X` → 规划 `-Y`”且 Tuna 位于该侧，不能拿来替换接近侧硬门。

路由包含两个不同职责：`demo.py` 在任何运动命令前把精确 Pudding **重定向**到专属 planner；通用 `pick_place_planner.py` 若被直接错误调用并收到 Pudding，则必须 **raise** 安全异常，不能在内部重定向或回退。正常 demo 路径不通过 try/catch 把该异常转回旧路径。

当前共享 `GRIPPER_EFFORT` 的默认值经代码核对为 140 N；Pudding 的 140 N 仍通过专属显式参数发送，既不改共享默认值，也不假设未来共享值永远不变。

第一阶段继续禁止与 Tuna 共享 monitor、状态机或滚动基础设施。两种对象的几何、候选和恢复语义不同；任何跨对象抽象留给独立设计审阅。
